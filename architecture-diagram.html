Keycloak(SSO) · Istio ext_authz(oauth2-proxy→OPA) · 디바이스 인증서 mTLS · SAML 운영자 접속 · 4종 접속기록 로그 파이프라인을 실제 AWS 위에 구현한 구조.

1. 요청 처리 흐름 — 신뢰 경계와 2단계 ext_authz

점선 테두리 상자(oauth2-proxy / OPA)는 Istio 메시 멤버가 아니다 — 사이드카가 없어 자동 mTLS를 못 받는다. Keycloak은 일부러 별도 VPC(점선 경계)에 둬서, EKS가 뚫려도 SSO 발급 주체는 분리된 신뢰 경계에 남게 설계했다.

2. 접속기록 로그 4종 — 수집 경로와 공통 조인 키

①④는 수집기 코드를 직접 통제해서 그 자리에서 바로 account를 끼워 넣는다. ②③은 AWS 네이티브 export라 손댈 수 없어서, CloudWatch에 들어온 뒤 Lambda가 다시 읽어 구조화한다 — EKS 감사 로그는 비용 절감용 Infrequent Access 클래스라 구독 필터가 안 돼서 5분 스케줄 폴링으로 우회한다.
